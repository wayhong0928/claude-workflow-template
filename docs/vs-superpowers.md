# 本 template 與 Superpowers 的差異

[Superpowers](https://github.com/obra/superpowers) 是 Claude Code 等 coding agent 常見的 skill 套件。下表比較兩者的做法，Superpowers 那一欄每列都附原始檔連結（固定在 commit `bb92a77`，之後上游改版，行號可能對不上）。

| 面向 | Superpowers | 本 template | 出處（Superpowers） |
|---|---|---|---|
| 處理的工作 | 軟體開發方法論：git worktree、TDD 紅綠循環、分支收尾 | 以寫作與研究為主的知識型專案（論文、筆記），程式專案也能用 | [README.md L3](https://github.com/obra/superpowers/blob/bb92a77741419a4ab5f06e711a283343f1ada0c3/README.md#L3)、[README.md L308–L322](https://github.com/obra/superpowers/blob/bb92a77741419a4ab5f06e711a283343f1ada0c3/README.md#L308-L322) |
| skill 叫用 | 只要有百分之一可能適用就必須叫，連釐清問題、看程式碼都排在叫 skill 之後 | 按需載入；只有派 subagent 前由 hook 強制先載 `dispatch-template` | [skills/using-superpowers/SKILL.md L10–L20](https://github.com/obra/superpowers/blob/bb92a77741419a4ab5f06e711a283343f1ada0c3/skills/using-superpowers/SKILL.md#L10-L20) |
| 委派 | 計畫交接時二選一：每個任務派一個新 subagent 實作、做完派審查、最後審整條分支；或在主對話逐項做，最後派一次審查 | 「有收益才委派」，主對話自己做是預設；派工要說得出理由並顯式指定 model | [README.md L316](https://github.com/obra/superpowers/blob/bb92a77741419a4ab5f06e711a283343f1ada0c3/README.md#L316)、[skills/subagent-driven-development/SKILL.md L12](https://github.com/obra/superpowers/blob/bb92a77741419a4ab5f06e711a283343f1ada0c3/skills/subagent-driven-development/SKILL.md#L12) |
| 要不要停下來問人 | 執行計畫時不停，自己裁決並記進 ledger；只有不可逆、安全、外部副作用、計畫爛到只能猜這四種情況才停 | 升級到 opus 仍不過就停，把失敗軌跡交給使用者裁決；高風險判斷兩路答案分歧時擺給使用者，不自己硬選 | [skills/subagent-driven-development/SKILL.md L17–L31](https://github.com/obra/superpowers/blob/bb92a77741419a4ab5f06e711a283343f1ada0c3/skills/subagent-driven-development/SKILL.md#L17-L31)、[skills/executing-plans/SKILL.md L32–L43](https://github.com/obra/superpowers/blob/bb92a77741419a4ab5f06e711a283343f1ada0c3/skills/executing-plans/SKILL.md#L32-L43) |
| 驗收 | 宣告完成前，同一個 agent 自己跑指令看輸出；subagent 流程裡每個任務另派審查 | 依產出風險分三級；第 2 級派 fresh-context `verifier`，只給驗收條件不給推理；高風險再加 opus 第二意見 | [skills/verification-before-completion/SKILL.md L14–L21](https://github.com/obra/superpowers/blob/bb92a77741419a4ab5f06e711a283343f1ada0c3/skills/verification-before-completion/SKILL.md#L14-L21)、[skills/subagent-driven-development/SKILL.md L12](https://github.com/obra/superpowers/blob/bb92a77741419a4ab5f06e711a283343f1ada0c3/skills/subagent-driven-development/SKILL.md#L12) |
| 約束方式 | 靠 prompt：`EXTREMELY-IMPORTANT` 標籤、Red Flags 表；唯一的 hook 是 SessionStart，用來注入 using-superpowers | prompt 加 hook：派工沒載模板、回合寫出控制字元會被擋，context 過長會被提醒 | [skills/using-superpowers/SKILL.md L10–L50](https://github.com/obra/superpowers/blob/bb92a77741419a4ab5f06e711a283343f1ada0c3/skills/using-superpowers/SKILL.md#L10-L50)、[hooks/hooks.json](https://github.com/obra/superpowers/blob/bb92a77741419a4ab5f06e711a283343f1ada0c3/hooks/hooks.json)、[hooks/session-start L18–L41](https://github.com/obra/superpowers/blob/bb92a77741419a4ab5f06e711a283343f1ada0c3/hooks/session-start#L18-L41) |
| 跨 session 接續 | 以計畫為單位：ledger（`progress.md`）記到哪一步，compact 或換執行者後照 ledger 接著做；整條分支審完就刪掉這個計畫的 workspace | session_log 加 SessionStart 注入、TODO，以專案為單位長期留存 | [skills/executing-plans/SKILL.md L115–L139](https://github.com/obra/superpowers/blob/bb92a77741419a4ab5f06e711a283343f1ada0c3/skills/executing-plans/SKILL.md#L115-L139)、[skills/executing-plans/SKILL.md L103–L104](https://github.com/obra/superpowers/blob/bb92a77741419a4ab5f06e711a283343f1ada0c3/skills/executing-plans/SKILL.md#L103-L104) |
| 怎麼進化 | 用 eval 工具驅動真實的 agent CLI、依驗收條件評分來調 skill；README 列出 16 種 agent 的安裝方式 | 從實際踩過的坑長出來：同一個錯一再發生才改成 hook，並補回歸測試；只針對 Claude Code | [docs/testing.md L25–L27](https://github.com/obra/superpowers/blob/bb92a77741419a4ab5f06e711a283343f1ada0c3/docs/testing.md#L25-L27)、[README.md L9–L25](https://github.com/obra/superpowers/blob/bb92a77741419a4ab5f06e711a283343f1ada0c3/README.md#L9-L25) |

一句話版本：Superpowers 讓 agent 照計畫不中斷地自主寫幾個小時程式（[README.md L44](https://github.com/obra/superpowers/blob/bb92a77741419a4ab5f06e711a283343f1ada0c3/README.md#L44)）；本 template 給同時管好幾個專案的研究生用，重點是錯誤不進論文、token 省著用、跨 session 接得上。兩邊在委派和要不要停下來問人這兩點上方向相反。
